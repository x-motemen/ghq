== NAME

ghq - Manage remote repository clones

== DESCRIPTION

'ghq' provides a way to organize remote repository clones. When you clone a remote repository by +ghq get+, ghq makes a directory under a specific root directory (by default +~/ghq+) using the remote repository URL's host and path.

    $ ghq get https://github.com/x-motemen/ghq
    # Runs `git clone --recursive https://github.com/x-motemen/ghq ~/ghq/github.com/x-motemen/ghq`

You can also list local repositories (+ghq list+).

== SYNOPSIS

[verse]
ghq get [-u] [-p] [--shallow] [--vcs <vcs>] [--look] [--silent] [--branch <branch>] [--no-recursive] [--parallel] [--bare] [--clean-bare] [--partial blobless|treeless] [<repository>...]
ghq list [-p] [-e] [--vcs <vcs>] [--unique] [--bare] [<query>]
ghq create [--vcs <vcs>] [--bare] <repository>
ghq rm [--dry-run] [--bare] <repository>...
ghq migrate [-y] [--dry-run] <repository-directory>
ghq root [--all]

A '<repository>' can be a repository URL, '<host>/<user>/<project>',
'<user>/<project>', or '<project>'.

== COMMANDS

get::
    Clone one or more remote repositories under ghq root directory (see
    <<directory-structures,DIRECTORY STRUCTURES>> below). `ghq clone` is an alias for this command.
    With no repository arguments, read one repository specification per line
    from standard input. The local repository path is printed to standard
    output for each successful clone, update, or existing repository. +
    If the repository is
    already cloned to local, nothing will happen unless '-u' ('--update')
    flag is supplied. For regular Git checkouts, this runs
    'git pull --ff-only --no-recurse-submodules' when the current branch has
    an upstream, or 'git fetch --no-recurse-submodules' otherwise.
    When you use '-p' option, the repository is cloned via SSH protocol. +
    If there are multiple +ghq.root+ s, existing local clones are searched
    first. Then a new repository clone is created under the primary root if
    none is found. +
    With '--shallow' option, ghq limits the initial checkout using the
    backend's shallow or lazy mode: Git uses '--depth 1', Subversion uses
    '--depth immediates', git-svn starts at the latest changed revision, and
    Darcs uses '--lazy'. Other backends ignore this option. +
    With '--branch' option, you can clone the repository with specified
    branch. This option is currently supported for Git, Mercurial,
    Subversion, git-svn, and Pijul (where it selects a channel).
    For Git, this also passes '--single-branch'. A branch or Git tag can
    also be specified by appending '@<branch>' to the repository argument;
    this takes precedence over '--branch'. +
    Git submodules are cloned recursively by default and updated after a
    successful pull. Use '--no-recursive' to skip these submodule operations. +
    With '--parallel' option, repositories are processed concurrently and
    VCS command output is suppressed. With '--silent' option, logging and
    VCS command output are suppressed; local repository paths are still
    printed to standard output. +
    With '--look' option, start a shell in the repository after getting it
    (the first repository when multiple repositories are supplied). +
    With '--bare' option, a "bare clone" will be performed (for Git
    repositories only, 'git clone --bare ...' eg.). The on-disk directory
    receives a '.git' suffix (e.g. '<root>/host/user/repo.git'). +
    With '--clean-bare' option, a bare clone is performed but the bare
    gitdir is placed as a '.git' subdirectory of an unsuffixed parent
    (e.g. '<root>/host/user/repo/.git'). This layout keeps the repository
    directory name clean and allows Git worktrees to live as sibling
    subdirectories:
+
....
repo/
├── .git/       # bare repository
├── main/       # worktree
├── feature/    # worktree
└── bugfix/     # worktree
....
+
'--clean-bare' implies '--bare'. Passing both together is not an error:
'--bare' is ignored (with a warning) and the clone follows the
'--clean-bare' layout. +
    With '--partial' option, a "partial clone" will be performed (for Git
    repositories only, in 'blobless' mode, 'git clone --filter=blob:none ...',
    in 'treeless' mode, 'git clone --filter=tree:0 ...' eg.).

list::
    List locally cloned repositories. If a query argument is given, only
    repositories whose names contain that query text are listed. '-e'
    ('--exact') forces the match to be an exact one (i.e. the query equals to
    _project_, _user_/_project_ or _host_/_user_/_project_). Exact matching
    is case-sensitive. Plain queries match the path without the host,
    ignoring case when the query contains no uppercase letters. A host
    prefix limits results to that exact host. +
    If '-p' ('--full-path') is given, the full paths to the repository root are
    printed instead of relative ones. '--unique' prints the shortest
    unambiguous path suffix for each repository and takes precedence over
    '--full-path'. '--vcs <vcs>' restricts results to that VCS backend. +
    Both regular and bare repositories are listed. '--bare' interprets a
    repository URL query using the classic bare layout ('repo.git'); it
    does not filter the list to bare repositories.

root::
    Prints repositories' root (i.e. `ghq.root`). Without '--all' option, the
    primary one is shown. '--all' also includes secondary and URL-specific roots.

rm::
    Remove one or more local repositories after confirmation. '--dry-run'
    prints the planned removal without prompting or deleting anything.
    Use '--bare' for the classic bare layout ('repo.git'); omit it for
    the unsuffixed '--clean-bare' layout. +
    When removing a Git repository with detected linked worktrees, ghq first
    removes those worktrees with 'git worktree remove --force', including
    worktrees outside ghq roots and their uncommitted changes. The confirmation
    prompt and '--dry-run' output list the affected worktree paths. +
    If a linked worktree is locked, removing its main repository stops with an
    error. Worktrees deleted earlier are not restored; the main repository and
    the locked worktree remain. +
    Linked worktrees of classic bare repositories ('repo.git') are currently
    not detected. Removing such a repository with '--bare' leaves its external
    worktrees in place with broken Git metadata references; they are not listed
    in the confirmation prompt or '--dry-run' output.

create::
    Initialize a new local repository under ghq root and print its path.
    '--vcs <vcs>' selects the backend explicitly. Git, Mercurial, Darcs,
    Pijul, Fossil, and Bazaar support this command. '--bare' creates a
    bare Git repository with a '.git' directory-name suffix.

migrate::
    Migrate an existing repository directory to the ghq-managed directory structure.
    The command detects the VCS backend, retrieves the remote URL, and moves
    the repository to the appropriate location under ghq root.
    For Git, the remote is 'origin' if available, otherwise the first remote.
    Linked Git worktrees and submodules cannot be migrated independently.
    When migrating a main Git checkout with linked worktrees, ghq attempts
    to repair their references after moving it. '--dry-run' prints the
    planned move without prompting; '-y' skips confirmation for an actual move.

== CONFIGURATION

Configuration uses 'git-config' variables.

ghq.root::
    The path to directory under which cloned repositories are placed. See
    <<directory-structures,DIRECTORY STRUCTURES>> below. Defaults to +~/ghq+. +
    This variable can have multiple values. If so, the last one becomes
    primary one, used for new clones unless a URL-specific root overrides it.
    You may want to specify "$GOPATH/src" as a secondary root, expanding
    environment variables when setting the configuration value.

ghq.user::
    In ghq, when specifying only the repository name without slashes as in `ghq get {{Project}}`,
    ghq attempts to auto-complete the repository owner.
    This option explicitly specifies the owner. Otherwise, ghq tries these
    sources in order: `GITHUB_USER`, hub configuration, `credential.username`
    matched against `https://github.com` (or `https://$GITHUB_HOST` when
    `GITHUB_HOST` is nonempty), `github.user`, a GitHub API lookup by `user.email`,
    and `user.username`. Finally, it falls back to `USER` (or `USERNAME` on Windows).
    The credential lookup uses that GitHub host independently of the repository
    URL and `ghq.defaultHost`.
    The API lookup makes a network request if earlier sources have not supplied
    a username and `user.email` is configured. Set `ghq.user` to select an owner
    directly and skip this discovery.

ghq.completeUser::
    Controls owner completion for `ghq get` and defaults to `true`.
    Rather than using your own username for owner completion,
    you may want to complete the owner with the same name as the repository.
    For example, fetch `ruby` as `github.com/ruby/ruby`,
    `vim` as `github.com/vim/vim`, and `peco` as `github.com/peco/peco`.
    If you prefer this behavior, set this option to `false` to switch the owner completion method.
    `ghq create` and `ghq rm` always use the detected username when only a project name is given.

ghq.defaultHost::
    The default host used when the repository specification omits the host.
    For example, `ghq get owner/project` normally resolves to `github.com/owner/project`.
    If this option is set, the specified host will be used instead.

ghq.<url>.vcs::
    For repositories without a built-in VCS choice, this option explicitly
    selects the VCS backend instead of detecting it. The URL is matched
    against '<url>' using 'git config --get-urlmatch'. +
    Accepted values are "git", "github" and "codecommit" (aliases for "git"), "subversion",
    "svn" (an alias for "subversion"), "git-svn", "mercurial", "hg" (an alias for "mercurial"),
    "darcs", "pijul", "fossil", "bazaar", and "bzr" (an alias for "bazaar"). +
    To get this configuration variable effective, you will need Git 1.8.5 or higher.

ghq.<url>.root::
    The "ghq" tries to detect the remote repository-specific root directory. With this option,
    you can specify a repository-specific root directory instead of the common ghq root directory. +
    The URL is matched against '<url>' using 'git config --get-urlmatch'.

Since `ghq get` runs `git clone` for Git repositories, git's own configuration applies as
well. For example, `clone.defaultRemoteName` changes the name of the created remote, which
is `origin` by default. +
To get this configuration variable effective, you will need Git 2.30 or higher.

=== Example configuration (.gitconfig):

....
[ghq "https://git.example.com/repos/"]
vcs = git
root = ~/myproj
....

The subsection URL selects remote URLs to which these settings apply; it is
not a local path or a URL rewrite. In this example, repositories under
`https://git.example.com/repos/` use Git and are cloned beneath `~/myproj`.
For example, `ghq get https://git.example.com/repos/team/tool` creates a new
clone at `~/myproj/git.example.com/repos/team/tool`. The hostname and repository
path are preserved; `root` only changes the directory beneath which they are placed.
See https://git-scm.com/docs/git-config#Documentation/git-config.txt---get-urlmatch[Git's URL matching rules]
for details.

HTTPS and SSH URLs are matched separately. To apply the same settings to
`git@git.example.com:repos/team/tool`, which ghq normalizes to
`ssh://git@git.example.com/repos/team/tool`, add an SSH subsection:

....
[ghq "ssh://git@git.example.com/repos/"]
vcs = git
root = ~/myproj
....

If the repository already exists under one of the configured roots, ghq reuses
that clone rather than moving it to the URL-specific root. Setting `GHQ_ROOT`
overrides both the common and URL-specific roots.

== ENVIRONMENT VARIABLES

GHQ_ROOT::
    If nonempty, replaces both common and URL-specific root settings.
    Multiple paths can be separated by ':' on Unix or ';' on Windows.
    The first path is the primary root; subsequent paths are searched for
    existing repositories.

GHQ_LOOK::
    Set by '--look' in the new shell to the repository path relative to its ghq root.

SHELL::
    The shell started by '--look'. If unset, ghq uses `COMSPEC` on Windows
    or `/bin/sh` on other platforms.

NO_COLOR::
    A nonempty value disables colored log prefixes.

== [[directory-structures]]DIRECTORY STRUCTURES

Local repositories are placed under 'ghq.root' using '<host>/<repository path>'.
The hostname excludes the port, and a trailing '.git' is removed unless
the classic '--bare' layout is requested.

....
~/ghq
|-- git.example.com/
|   `-- repos/
|       `-- team/
|           `-- tool/
`-- github.com/
    |-- google/
    |   `-- go-github/
    |-- x-motemen/
    |   `-- ghq/
    `-- urfave/
        `-- cli/
....
